## Four NO-GO findings

### Finding 1 — feature count 543, plan-doc requires 545 (+/- 1)

The plan-doc encodes a 545-feature precondition rooted in shijithpk's 545-feature file (`india_ls_seats_545.geojson`). The ramSeraph release ships 543 features.

543 IS the current constitutional Lok Sabha elected seat count (the 2 nominated Anglo-Indian seats were abolished in 2019 via the 104th Constitutional Amendment). So in absolute terms 543 is correct. But the plan-doc gating bar of 545 (+/-1) was set by the user-mandated recon-gate contract, and 543 fails it. More importantly, the shortfall is not in any specific state — it is the legitimate constitutional adjustment — so the count-test alone is borderline. Findings 2-4 are the structural blockers.

### Finding 2 — 39 features marked `"Pre delimitation"`; SIX entire states have ZERO active coverage

Per-state breakdown (where `status` distribution is non-trivial):

| State (LGD)        | total | active | pre_delim |
| ------------------ | ----: | -----: | --------: |
| s_lgd=1  J&K       |     6 |      0 |         6 |
| s_lgd=12 Arunachal |     2 |      0 |         2 |
| s_lgd=13 Nagaland  |     1 |      0 |         1 |
| s_lgd=14 Manipur   |     2 |      0 |         2 |
| s_lgd=18 Assam     |    14 |      0 |        14 |
| s_lgd=20 Jharkhand |    14 |      0 |        14 |

Aggregate: 504 active + 39 pre-delim = 543 total. Six entire states have **zero active PC boundaries** in the ramSeraph release. The pre-delim features are real polygons — but they encode *older* delim cycles (e.g. composite pre-2019 J&K including Ladakh, pre-2008 Assam, pre-2008 Jharkhand). Joining ECI 2024 election results to a pre-delim PC boundary produces silently-wrong choropleth fills.

Even Telangana (s_lgd=36, post-2014 carve-out) has 17 active PCs but mis-keyed (see Finding 4).

### Finding 3 — no `lgd_pc_code` property

CLAUDE.md section 3 identifier discipline + `docs/reference/identifiers.md` require LGD codes for non-elections identifiers. The PC layer's "natural" LGD code (the official LGD-portal Parliament Constituency Code) is NOT present. Candidate keys inspected:

- `pc_id` (e.g. 201, 301, 2801, ...) — not an LGD code; see Finding 4
- `pc_no` — within-state ordinal (1..N); not globally unique

The frontend boundary loader (`frontend/src/lib/boundaries.ts`) uses LGD codes as the join key on every other layer (state=`State_LGD`, district=`dist_lgd`, subdistrict=`subdt_lgd`, village=`vil_lgd`). PC currently has no frontend consumer at all (no `"pc"` member in the `GeoLevel` union as of `b696a8fc`), so we have flexibility — but adopting a layer with no LGD-grade identifier locks us out of the canonical-join contract before any consumer is built.

### Finding 4 — `pc_id` is unstable (Telangana keeps Andhra Pradesh's old prefix)

Sanity test: is `pc_id == st_code * 100 + pc_no`? Result: 44 mismatches (out of 543).

```
mismatch: st_code=36 pc_no=1 expected=3601 got=2801 pc_name=ADILABAD(ST)
mismatch: st_code=36 pc_no=2 expected=3602 got=2802 pc_name=PEDDAPALLE (SC)
mismatch: st_code=36 pc_no=3 expected=3603 got=2803 pc_name=KARIMNAGAR
mismatch: st_code=36 pc_no=4 expected=3604 got=2804 pc_name=NIZAMABAD
mismatch: st_code=36 pc_no=5 expected=3605 got=2805 pc_name=ZAHIRABAD
...
```

All 17 Telangana PCs use `28xx` (Andhra Pradesh's old st_code) instead of `36xx` (TS st_code). The same drift accounts for the remaining 27 mismatches (D&NH, etc.). This means `pc_id` is a legacy frozen key from pre-2014 mapping, not a derivable post-bifurcation identifier. Any join key built on `pc_id` would silently mis-attribute Telangana data to Andhra Pradesh.

## Why we keep shijithpk

The current PC layer (`datasets/ephemeral/india_ls_seats_545.geojson` + canonical `datasets/boundaries/in/pc/delim=2024/all.geojson` at 1.28 MB raw, gzipped well under the 500 KB ceiling) was QGIS-traced over the 2024 ECI delimitation PDF. Its provenance is weaker (no LGD-keyed survey lineage) but it satisfies the three properties ramSeraph does not:

1. Single delim vintage (2024) across all 545 features. No pre-delim contamination.
2. Complete state coverage (no zero-active-PC states).
3. Stable internal identifier (`pc_no` + `pc_name` indexed against the 2024 ECI gazette).

Since there is no frontend PC consumer today, this is a data-fitness call only: we keep the layer that does not cause regressions when a consumer is eventually wired.

## Re-evaluation triggers

Re-run `tools/boundaries/recon_d6_pc.py` and re-open D.6 when ANY of the following changes upstream:

- ramSeraph publishes a release where the six structural-gap states (J&K, Arunachal, Nagaland, Manipur, Assam, Jharkhand) all have `status=" "` (active) features.
- ramSeraph adds an `lgd_pc_code` property (or the documented LGD-portal PC code under any name).
- The Telangana `pc_id` block is rewritten to use `36xx` (or any state-correct prefix).
- A new upstream LGD-grade PC release with `delim=2024` and 543 active features ships from any maintainer.

Independent of upstream: re-evaluate IF a frontend PC consumer is proposed (e.g. a Lok Sabha cycle tracker). At that point the citizen-facing risk of the current shijithpk layer must be re-weighed against ramSeraph's structural gaps.
