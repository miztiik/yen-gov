## Why this exists

Parent sub-row B1.4 reads as one row but expands across nine ingest modules and thirteen `write_artifact` call sites, each emitting a different indicator shape (national-grain, state-grain, facet-keyed, multi-indicator). The re-point is NOT mechanical: each family needs a per-indicator mapping decision (entity_id source, concept_id binding, facet column carve-out, source_id derivation triple). Bundling all nine into one PR exceeds the parent plan's correction-level discipline (CLAUDE.md section 6; 4+ files structural -> propose breakdown first) and would swamp review. Per parent plan section 24.5 we spawn this sub-plan.

## Scope

In scope: every `write_artifact(...)` call site under `backend/yen_gov/sources/iced_*` re-pointed onto `yen_gov.canonical.csv_writer.write_csv` per the file-class contract in `datasets/data/_schema/columns.json`. Per parent plan section 23.1 the OLD `core/io.write_artifact` survives until B3; this sub-plan does NOT delete it. Per parent B1 sub-plan §B1.4-B1.6, each family records its alongside-vs-instead-of choice in the family PR body.

Out of scope: rbi_* (B1.5), cea_* / datagovin_ogd / india_geodata / pipeline / cli / canonical/adapters (B1.6); deletion of `core/io.write_artifact` or any parquet artefact (B3); `entities/source.csv` builder (B2a); concept-catalogue authoring (B2a).

## Pre-flight - source-id + concept-id readiness

Each ingest must derive `source_id` via `yen_gov.canonical.citation.derive_source_id(producer, title, vintage)` (CLAUDE.md Holy Law #9, section 12). The validator gate (B1.3) enforces `source_id` FK presence in `datasets/data/entities/source.csv`; that file is built by B2a. While B2a is upstream, the writer (B1.2) does NOT itself check the FK; the validator does. Each family PR runs the writer and an isolated writer-unit assertion; the FK-presence assertion is exercised once `entities/source.csv` lands (B2a) via the existing `fk-validator` gate run on the suite. No mock `entities/source.csv` is created in this sub-plan (CLAUDE.md Holy Law #7). If a family's concept_id does not yet exist in `datasets/data/concepts.csv` (also B2a), the family PR records the gap in its PR body + creates a follow-up issue tag in the sub-row notes.

### B1.4.1..9 per-family pattern (binding)

Each family PR:

1. Imports `write_csv` from `yen_gov.canonical.csv_writer` and `derive_source_id` from `yen_gov.canonical.citation`.
2. After (alongside) the existing `write_artifact(...)` call, builds the long-format CSV row list per the indicator's file class (`datasets/data/datapoints/geo/*.csv` for state-grain; same glob for national-grain rows with `entity_id="IN"` per parent plan F4 freeze).
3. Calls `write_csv(path=repo_root / "datasets/data/datapoints/geo" / f"{variable_id}.csv", file_class="datasets/data/datapoints/geo/*.csv", rows=csv_rows)`.
4. `variable_id` honours parent plan section 21.6 / 21.12: no `__`; kebab-case `<measure>-<unit>-<facet>` per ADR-0044; never grain-prefixed.
5. Records in PR body: (a) alongside-vs-instead-of choice + reason; (b) per-indicator (file_class, variable_id, entity_id source, source_id triple) table; (c) concept_id binding (or DEFER-to-B2a marker if missing).
6. Existing meadow-JSON output stays in place (alongside) for this sub-plan; instead-of is deferred to B3 per parent plan section 23.1.
7. Faceted indicators (e.g. iced_ghg "Sector|SubSector") split into per-facet variable_ids OR keep one variable_id with a facet column; the choice is recorded per indicator. Until the writer supports facet columns (csv_writer.py top-of-file note), split into per-facet variables.
8. Gate: `writer-unit` (the row-builder helper is unit-tested with a tmp_path fixture under `backend/tests/test_iced_<family>_csv_repoint.py`) + `suite-green` (full pytest at merge).

## Contract invariants (inherited from grandparent 22.4 + parent §Contract invariants)

1. Provenance FK mandatory: every CSV row carries `source_id` (Holy Law #9).
2. One-indicator-per-concept: each `variable_id` binds to one `concept_id` (FK to `concepts.csv`; gap allowed during B2a window with DEFER marker, never silently null).
3. Schema-per-file typed: rows handed to `write_csv` declare the file class explicitly; no `read_csv_auto` round-trip.
4. Static-first deterministic read: rows sorted upstream by (entity_id, time); no `datetime.now` in content columns.
5. ASCII-only + relative POSIX paths in any persisted artifact.
