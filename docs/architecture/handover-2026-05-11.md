# Handover — Per-state event identity + government as primary anchor (2026-05-11)

**Author**: agent session ending 2026-05-11 (after the 8-state ECI ingest commit `29da524`).
**Audience**: the next session (or contributor) who picks up the IA-reset thread.
**Companion docs**: [ADR-0023](decisions/0023-election-event-identity-per-place.md), [docs/concepts/government-vs-election.md](../concepts/government-vs-election.md), [TODO/IA-RESET-PLACE-FIRST-WITH-TOPIC-FRONT-DOOR.md](../../TODO/IA-RESET-PLACE-FIRST-WITH-TOPIC-FRONT-DOOR.md) §P2.5.

## What problem was solved

A citizen typing `/s/andhra-pradesh` (or any state outside the May-2026 cohort: AP, AR, BR, HR, JK, JH, MH, OD, SK, DL) saw an unrecoverable 404 because seven separate route components had hardcoded `const event = "AcGenMay2026"` and asked for `/data/elections/AcGenMay2026/S01/result.summary.json`. AP has never had a May-2026 election.

Root cause was structural, not a typo: the IA carried a global "Election" dropdown (from when AcGenMay2026 was the only ingested event) that encoded the federal falsehood that elections are nationally synchronous. India does not have a "current election"; each state has its own cycle (AP polled in 2024, Bihar in 2025, J&K in 2024 after six years of President's Rule, etc.).

Two subagents (Architect Gregor + Governance Strategist) consulted in parallel converged on the same diagnosis: kill the dropdown, make event identity per-place, and promote government-timeline (continuing condition) above election (discrete event) as the citizen's primary anchor. ADR-0023 is the canonical record.

## Lessons (worth memorising)

- **The Architect was right that subagent runs in parallel save real time** — Gregor + Strategist consultations done concurrently delivered convergent diagnoses in ~5 minutes. Subagent state-name guesses for ECI codes (S07/S13/S18/S27) were WRONG (gave Goa/HP/MP/UP instead of Haryana/Maharashtra/Odisha/Jharkhand); always cross-check against `events.py`.
- **A "graceful 404" is not a fix when the underlying control is conceptually wrong.** Skipping the B0 hotfix and going straight to B1+B2 saved a throwaway codepath.
- **Hand-authored data is not "stale by definition"** if it's small, citizen-meaningful, and validated by CI against a generated source. The `election-events.json` ↔ `events.py` consistency test makes the duplication safe.
- **Frozen-in-time principle**: government timelines are easier to ship correct (4 states done) than 10 more in a panic. Honest "coming soon" beats invented data.
- **"AcGenMay2026" must never appear in citizen-facing chrome** — the `display` field in `election-events.json` is the only label. Codes appear in URL path segments only when explicit (`/s/<state>/elections/<event_id>`), never in chrome strings.

## Update — 2026-05-24: PR #193 (Q1 elections-topic renderer + PR-2 `default`-field retirement)

PR #193 (merge commit `c8700b4f`) advanced the IA-RESET elections thread along two coordinated axes. Canonical rationale lives in [indicators.md §Decisions-journal-2026-05-24](frontend/indicators.md); the doc-class routing contract (CLAUDE.md §5) keeps this entry to status-and-pointer only.

**What landed.**

- `/s/<state>/t/elections` now renders the new `kind: "election"` artifact (polymorphic dispatch, lazy-loaded `election-events.json`, `defaultEventForState(state_code)` resolution, collapsed `<details>` "other elections" list). Topic-catalogue schema bumped v1.3 → v1.4 (`id` is conditionally required by `kind`). The 5-paragraph operator-narrative `topic.notes` is no longer rendered to citizens (citizen-bleed retirement).
- New `/s/<state>/elections/<event_id>` deep-link route via `StateElection.svelte`. Closes IA-RESET §P2.6 follow-up item #4 above (partially — chip-strip index still deferred).
- `default: true` boolean retired from the entire spine: `election-events.schema.json` v1.0 → v1.1 (breaking), 23 on-disk rows stripped, seed-code field/invariant removed, `is_default` column dropped from the Parquet emit, Pydantic `extra="forbid"` guard added as the symmetric replacement. The HP regression that motivated PR #191 (8 states silently rendering the OLDEST event because `default: true` was unset) is fixed at source — selector reads `max(polled_on)`, no per-row maintenance burden survives.

**Deferred from PR #193 (future work, indexed here for the next session).**

These are the explicit "we chose not to do this in PR #193" items. Promote any one of them to an active PR when the prerequisite gates clear (noted per item). Rationale for each is in [indicators.md §Decisions-journal-2026-05-24 §Deferred](frontend/indicators.md).

1. **Chip-strip index at `/s/<state>/elections`** (plural, no event). The deep-link `/s/<state>/elections/<event>` shipped; the plural index did not. Promote when ≥1 state has ≥2 events on file. Today every state has exactly one assembly event so the chip strip would be cosmetic — same gate as the original follow-up #4 above.
2. **Election timeline strip on `/s/<state>/t/elections`.** A chronological chip axis would be a stronger citizen surface than the current header-card + collapsed `<details>` pattern. Overlaps in scope with item #1; promote together when ≥1 state crosses 4+ events.
3. **"Next election due" countdown chrome.** Uses the existing `term_end_estimated` field (typically `polled_on + 5 years`). Needs Hans + Jony design pass on placement, copy when overdue, and interaction with the "Latest election" recency banner (ADR-0023 §Decision/3).
4. **Government-card cross-link on `/s/<state>/elections/<event>`.** Per ADR-0023 §Doctrine, election is the cause and government is the consequence. Today the new page links forward to `/lab` (results) and `/compare` (cross-state) but not sideways to the government this election produced. Non-trivial editorial mapping for cohort events (LS-2024 elected MPs, not state CMs); needs explicit decision before wiring.
5. **Inline results preview on the topic page** (top-3 parties, turnout pill, women-elected pill). Today the topic shows event identity only; the actual results are one click away on `/lab/<state>/<event>`. Real component work; would need a Tier-A contract test against `dim_acs` / `elections_candidacies` to prevent silent drift.
6. **Promote turnout %, women-candidate %, party-share to first-class `indicator` artifacts under the elections topic.** Today these live as derivable facts in per-event Parquets but not as catalogue entries the StateTopic renderer can dispatch on. Unlocks `[election header card] + [turnout choropleth] + [women-elected ranked list] + …` via existing polymorphic dispatch, with zero new component code. Blocked on the canonical-store pivot for elections — see [docs/archive/plans/20260517-canonical-long-format-pivot.md](../archive/plans/20260517-canonical-long-format-pivot.md).
7. **Topic-grid `/t/elections` cross-state widening.** The per-state path `/s/<state>/t/elections` now dispatches the election artifact; the global `/t/elections` page does NOT (different renderer wiring in `TopicLanding.svelte`). The cross-state question is "which states polled most recently / how does turnout compare nationally" — which is the indicator-promotion path in #6 above, not the per-event-card path. Promote after #6 lands.

**Designs explicitly rejected by PR #193 (do NOT re-propose without an ADR).**

The full reasoning is in [indicators.md §Decisions-journal-2026-05-24 §Rejected-designs](frontend/indicators.md); compact list here for fast-entry:

- (QR1) Bake the concrete `event_id` literal (e.g. `"AcGenMay2026"`) into `topics.json` — Federal Falsehood, can't satisfy a 31-state catalogue with one global default.
- (QR2) Render `topic.notes` as citizen-facing prose above the artifact list — operator-narrative citizen-bleed.
- (QR3) Render the election artifact for country or district scope — re-introduces the ADR-0023 Federal Falsehood at a different surface.
- (QR4) Add a `<select>` event picker on `/s/<state>/t/elections` — duplicates the per-state picker contract already on `/s/<state>` from ADR-0023 Addendum 2026-05-13.
- (2R1) Keep `default: true` and patch the loader's tie-breaker (sort by `polled_on DESC` before `rows[0]`) — the field would still be decorative (CLAUDE.md §10), every new event row would still have to either set or clear it correctly.
- (2R2) Soft-retire `default: true` with deprecation in v1.0 changelog, leave it readable for one cycle — Holy Law #5 (no band-aids); selector swap in PR #191 already silenced runtime effect, the carrier is truly dead.
- (2R3) Replace `default: true` with explicit `default_for: ["S22", "S29"]` array — same maintenance trap with extra coupling.
