## Why this exists

Parent sub-row B1.5 reads as one row but expands across five distinct ingest modules under `backend/yen_gov/sources/rbi_*`, each with its own indicator-mapping decisions (national vs state grain, single-indicator vs multi-spec loop, facet shape, source-id triple). The `rbi_xlsx` family alone iterates over a multi-indicator `SHIPPED_SPECS` registry and emits one artifact per spec inside its single `write_artifact` call site. Per CLAUDE.md correction-level discipline (4+ files structural -> propose breakdown first) and grandparent plan section 24.5, the right shape is a thin parent row + this sub-plan, mirroring the B1.4 precedent (archived at [docs/archive/plans/20260604-b1.4-iced-repoint-subplan.md](../docs/archive/plans/20260604-b1.4-iced-repoint-subplan.md)).

## Scope

In scope: every `write_artifact(...)` call site under `backend/yen_gov/sources/rbi_*` re-pointed onto `yen_gov.canonical.csv_writer.write_csv` per the file-class contract in `datasets/data/_schema/columns.json`. Per grandparent plan section 23.1 the OLD `core/io.write_artifact` survives until B3; this sub-plan does NOT delete it. Each family records its alongside-vs-instead-of choice in the family PR body. The local helper `rbi_hbs/emit.py::write_artifact` (a thin per-module JSON dumper, distinct from `core.io.write_artifact`) is in scope only where a re-pointed caller no longer needs it; deletion is deferred to B3.

Out of scope: cea_* / datagovin_ogd / india_geodata / pipeline / cli / canonical/adapters (B1.6); deletion of `core/io.write_artifact` or any parquet artefact (B3); fetch-code delete (B4); `entities/source.csv` builder (B2a); concept-catalogue authoring (B2a).

## Pre-flight - source-id + concept-id readiness

Each ingest must derive `source_id` via `yen_gov.canonical.citation.derive_source_id(producer, title, vintage)` (CLAUDE.md Holy Law #9, section 12; ADR-0042 vintage semantics). The validator gate (parent B1.3) enforces `source_id` FK presence in `datasets/data/entities/source.csv`; that file is built by B2a. While B2a is upstream, the writer (parent B1.2) does NOT itself check the FK; the validator does. Each family PR runs the writer and an isolated writer-unit assertion; the FK-presence assertion is exercised once `entities/source.csv` lands (B2a) via the existing `fk-validator` gate run on the suite. No mock `entities/source.csv` is created in this sub-plan (CLAUDE.md Holy Law #7). If a family's concept_id does not yet exist in `datasets/data/concepts.csv` (also B2a), the family PR records the gap in its PR body + leaves a DEFER-to-B2a marker; no row is emitted with a silently null concept_id.

### B1.5.1..5 per-family pattern (binding, mirrors B1.4.1..9)

Each family PR:

1. Imports `write_csv` from `yen_gov.canonical.csv_writer` and `derive_source_id` from `yen_gov.canonical.citation`.
2. After (alongside) the existing `write_artifact(...)` call, builds the long-format CSV row list per the indicator's file class (`datasets/data/datapoints/geo/*.csv` for state-grain; same glob for national-grain rows with `entity_id="IN"` per grandparent plan F4 freeze).
3. Calls `write_csv(path=repo_root / "datasets/data/datapoints/geo" / f"{variable_id}.csv", file_class="datasets/data/datapoints/geo/*.csv", rows=csv_rows)`.
4. `variable_id` honours grandparent plan section 21.6 / 21.12: no `__`; kebab-case `<measure>-<unit>-<facet>` per ADR-0044; never grain-prefixed.
5. Records in PR body: (a) alongside-vs-instead-of choice + reason; (b) per-indicator (file_class, variable_id, entity_id source, source_id triple) table; (c) concept_id binding (or DEFER-to-B2a marker if missing).
6. Existing meadow-JSON output stays in place (alongside) for this sub-plan; instead-of is deferred to B3 per grandparent plan section 23.1.
7. Faceted indicators (e.g. rbi_xlsx specs that carry a `facet` field per row) split into per-facet variable_ids OR keep one variable_id with a facet column; the choice is recorded per indicator. Until the writer supports facet columns (csv_writer.py top-of-file note), split into per-facet variables.
8. `source_id` derivation: producer = "Reserve Bank of India"; title per family (e.g. "Handbook of Statistics on Indian Economy, Table 89" for rbi_hbs_ie_centre_deficits; "State Finances: A Study of Budgets, Statement N" for rbi_appendix_*; "State Finances: A Study of Budgets" for rbi_xlsx); vintage per ADR-0042 (publisher edition string, e.g. "2024-25").
9. Gate: `writer-unit` (the row-builder helper is unit-tested with a tmp_path fixture under `backend/tests/test_rbi_<family>_csv_repoint.py`) + `suite-green` (full pytest at merge).

## Contract invariants (inherited from grandparent 22.4 + parent §Contract invariants)

1. Provenance FK mandatory: every CSV row carries `source_id` (Holy Law #9).
2. One-indicator-per-concept: each `variable_id` binds to one `concept_id` (FK to `concepts.csv`; gap allowed during B2a window with DEFER marker, never silently null).
3. Schema-per-file typed: rows handed to `write_csv` declare the file class explicitly; no `read_csv_auto` round-trip.
4. Static-first deterministic read: rows sorted upstream by (entity_id, time); no `datetime.now` in content columns.
5. ASCII-only + relative POSIX paths in any persisted artifact.
6. LGD/ECI key separation preserved (writer never invents a shared parent); rbi_* state rows key on ECI state codes per existing parser output.
