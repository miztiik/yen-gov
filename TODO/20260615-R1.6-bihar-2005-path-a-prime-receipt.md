The catch — and the reason a half-ship is worse than a deferral — is in plan-doc Section 2.6.1's own forensic evidence:

> Root cause: path scaffolding at `backend/yen_gov/canonical/reingest/elections.py#L93` keys dirs by `election_year: int` (NOT `event_id`). Adapter at `backend/yen_gov/canonical/adapters/eci_ae_panel.py#L233` correctly groups by `(year, month)` and resolves `event_id_for(state_code, year, month)` against `EVENTS_BY_MONTH` ... — but both groups collide into the same `state=bihar/election=2005/` dir; second write overwrites/stacks.

The catalogue split + schema bump alone (the surgical ~50 LOC) would land *new event_ids that resolve to the same corrupted on-disk dir*. The mart writer's first-match-wins resolver would then attribute the corrupted rows (`5326 candidacy rows ≈ 1.97x expected`; `2092 ACs with stacked position-1 winners`; `28 negative-margin summary rows`; `84 winner==runnerup summary rows`) to whichever of the new event_ids sorts first — **moving the lie from one slug to two slugs without fixing the underlying corruption**.

The structural fix REQUIRES the writer kwarg change + Bihar-only re-emit + mart-resolver fix in the SAME PR, per Gregor's panel ruling: *"A Canonical Data Model is a promise about identity — when identity collapses, you fix the model, not the row."*

That's a Level-4 backend rip:

- Touches the `BatchEnvelope` writer flow (`backend/yen_gov/canonical/writer.py`)
- Touches the AE-panel adapter's writer-callsite + the `Period` shape it threads through
- Touches the mart writer's `_find_assembly_event` resolver
- Requires a Bihar-2005-only re-emit from the ephemeral upstream Statistical Report transcriptions
- Requires a `git mv` + migration-ledger entry + dir-deletion in datasets/
- Requires +2 contract tests (catalogue PK invariant + writer-entry assertion)

Plan-doc effort estimate: M → L (revised in Section 2.6.1). Real effort with proper safety: ~250-400 LOC across backend + datasets + tests, parallel-unsafe with R5/R7 because it touches the writer surface every adapter consumes.
