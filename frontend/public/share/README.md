# share/ - generated OG-card PNGs

Citizen-facing OG-card unfurl PNGs for `<state>/elections/<event>` +
`<state>/elections/` + `/t/elections/<event>` (national). Generated at
build time by `frontend/scripts/build-share-cards.ts` per R7 of
[TODO/20260615-state-election-event-page-redesign-plan.md](../../../TODO/20260615-state-election-event-page-redesign-plan.md).

## What ships

- `share/<state-slug>/<event_id>.png` - one 1200x630 PNG per
  state-scope row in `datasets/data/marts/elections/event_summary.csv`.
- `share/national/<event_id>.png` - one 1200x630 PNG per
  national-scope row.

## Why these aren't checked in

Generated bytes derived from the canonical mart + parties + states +
sources CSVs. Re-running `bun run build` (or `bun run build:cards`)
regenerates byte-identical output - committing them is the same
shape as committing a `dist/` or `node_modules/` blob: drift bait
without an upstream truth-source benefit.

## Wiring

`<svelte:head>` blocks on `frontend/src/routes/StateElection.svelte`,
`StateElectionsLanding.svelte`, and (when it lands) the national
elections route set the `og:image` + `twitter:image` meta to the
matching PNG path. When the PNG hasn't been generated yet (dev mode
without the build step), the meta tags 404 and the browser falls back
to text-only previews - degrades gracefully.
